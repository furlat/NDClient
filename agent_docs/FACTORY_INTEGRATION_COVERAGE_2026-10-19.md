### Public API route, without changing the Factory package

The existing public path is sufficient for this construction work: load the selected phase Resource during preparation, call its `to_clip()`, privately copy only the selected component input data, and call Factory `Source.make(parent, clip, layer_mask)`. That source function invokes each public `make_component(spec.input)` and retains the same source-space adaptation, clocks, shader/material isolation and geometry/lifecycle code used today. A small client-owned occurrence adapter can retain that normal handle and public sample/close/setter contract. The Factory phase Resource and shared source definitions remain immutable. No edits to private packaged assets or mutation of a live component's `parameters`, `settings`, `definition` or fixture owner object are justified.

The authored cue now explicitly selects its `cast` or native `application` scope and a finite `application_result` constructor projection. Empty scope preserves existing delivery behavior; persistent owner lifecycles keep their existing path. `PresentationEffectUse.constructor_input` names component IDs/input member, exact save effect and damage type. The abilities build checks those declarations against the actual public phase; the player does no schema/hash validation or field-name discovery. Actual scene/GPU construction stays in the existing bounded main-thread preparation lane. Static resources can warm during selection; unknown future application identities/outcomes cannot be filled with fixture data merely to preconstruct a node.

For Circle the component location is `components[id=receiving].input.components[id=received].input.application`. Fill its actual resolution `application_id`, actual recipient UUID for both identity members, factual `applied_damage > 0`, the matching SavingThrowFact's `succeeded`, and the actual damage type converted to the source's documented lower-case enum. The matching resolution/application relationship, not nearest event/time or target index, joins these facts. All other art settings remain unchanged. Missing required result evidence makes that visual component explicitly unavailable; it must not construct with example outcomes or stall authoritative world progression forever.

**Factory re-export is not intrinsically required for Circle:** its original constructor already accepts the complete application dictionary and the public phase/source APIs accept supplied component input data. The current pinned `construct.gd` → occurrence `_ready()` route simply does not expose that operand packet. Re-export would be appropriate if the Factory author chooses to publish a production-neutral wrapper/template/operand declaration. It is required only for behavior that the public constructors/setters genuinely cannot express, not as a blanket explanation for this adapter gap.
