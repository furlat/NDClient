## 5. Disclosure: retain spatial lookup through the accepted-state owner

**Status: concrete algorithm to finish and source-review; no implementation in
Appendix A.** Owner: existing Journal/Reducer context and `World.fold`, not a
new canonical field, world service or mutable global registry.

The old Opus append-only fold cannot replace schema16 omission/removal rules.
The restoration is the old computational principle: work on affected rows,
while retaining the exact current result.

The intended algorithm is:

1. Reuse an index only when its accepted-state context belongs to the exact
   input canonical state. Construct a cold index once when no such context
   exists; pure SDK callers without retained context must remain correct.
2. Retain reverse support-cell → object IDs, suppression-footprint → object IDs
   and support-cell → connector IDs. Reuse the exact current support and
   suppression geometry rules; anchor-only lookup is incomplete.
3. Maintain each object's exact support/suppression memberships at the existing
   add, replacement, movement, placement/removal and suppression update sites.
   Maintain connector memberships at their actual upsert/removal sites. Static
   definitions are immutable: index the actual resolved placement at its row
   writer, rather than inventing a global static-change rebuild. Staged stores
   with a different owner take the correct cold path.
4. Query only the entered disclosure cells/regions against this index. Form a
   private candidate set. Convert the current resent-ID Array to a local
   Dictionary once, preserving duplicate/refusal handling and original input
   order where those have semantics.
5. Run the unchanged final current predicates on candidates. Sort object
   candidates by retained insertion order before removing or capturing them;
   hash bucket traversal must not change preimages, first-removal order,
   erase/reappend order or suppression results. Connector order remains exact.
6. Fork index mutation privately for an operation. Adopt its final context only
   when the same canonical transaction is accepted. A refused operation must
   leave the old state and index untouched. No pointer to an intermediate state
   may be advertised as the accepted owner.

The existing context already owns exact-state sensory/mask reuse. Extending it
with derived spatial lookup avoids a new lifetime protocol. Canonical payloads,
recordings, protocol hashes and public schema do not acquire index fields.
Compiler staged/deep-copy/cold callers either use their matching derived owner
or the unchanged correct cold path; they cannot borrow Journal's newer state.

**Complexity claim to prove:** replace repeated GDScript geometry walks of all
retained objects with entered-cell queries plus affected candidate predicates
and changed membership work. Native Dictionary shallow copies needed for safe
copy-on-write can still be proportional to index size. Do not market this as
eliminating every O(N) copy, and do not build a persistent-container framework
to avoid that honest limit.

Detailed update sites, admission/rollback and cold fallback are in Appendix B.
Source review must close those sites before executable code is represented as
complete. Existing broad canonical/order/privacy controls qualify the whole
family afterward; no per-object or per-spell validation loop.

## 8. Preparation: charge before downstream admission, then bound actual units

**Status: bounded accounting repair plus source work for indivisible prefix
costs.** Owner: existing `ComponentRenderer.prepare` and shared preparation
budget, not a new scheduler.

Currently persistent-owner sampling, group construction, spatial coverage and
due-component collection execute before `audio.prepare`, presenters and outline
preparation. Their elapsed time is charged near the end. A later callee can
therefore admit work using a stale remainder even though the final total is
accurate.

The minimum repair accounts for uncharged prefix time immediately before each
budget-consuming downstream admission. Preserve the current subtraction of
time already charged by nested callees. At each boundary:

```text
# Algorithm only; variable spelling is not an approved production patch.
uncharged = elapsed_since_last_boundary - budget_already_charged_since_boundary
shared_used += max(0, uncharged)
move_boundary_to_now_and_current_shared_used
admit_next_existing_consumer_using_current_remainder
```

A single end-of-prefix flush is insufficient if subsequent outline scanning or
retirement adds another material uncharged section before another admission.
Complete caller accounting must neither omit that work nor charge nested work
twice. Required work keeps priority and already-required cleanup remains real.

This does not make one atomic owner scan a hard 2 ms unit. After the accounting
repair, remove redundant immutable discovery and split expensive independent
construction through existing private preparation continuation where the exact
source/owner/cut allows it. Retain a calculation only at complete current
membership, source, holder/slot, spatial disclosure and display-clock identity.
Clock-only or operation-only reuse is invalid for expiry, conditions and grants.

Partially built requirements remain private; only a complete set is published.
No new Timeline hold may be added for history/status work which previously
affected only sample readiness. Required/future surface coverage cannot share a
mutated map that reveals later cells early. Derive order/ownership before
deduplicating those passes. Keep the shared optional owner rotation and
required-before-optional policy unchanged.

## 10. Frame-cost attribution and performance comparison

Recover the source-confirmed structural work first. Preserve the unexplained
61.647 ms receipt. If a large unassigned interval remains after the family batch,
use one bounded investigation at the existing frame/postdraw/callback boundaries.

Keep these measures distinct:

- actual user submit → first visibly sampled mechanism/body;
- framed response available → canonical consumer/fold/compile/prepared opening;
- first usable discovery publication → decode start/completion → GPU/native
  admission → world publication → first sampled body;
- current media/world holds, startup readiness and choices available;
- whole after-ready frame distribution and maximum, plus command-window frames;
- ordinary Studio open/seek/control responsiveness and explicit four-view
  thumbnail batch availability.

`frame_ms` is an interval between profile calls, not the sum of nested CPU
leaves. Existing renderer CPU/GPU values can lag. Do not sum inclusive fields,
subtract different clocks as exclusive time, blame a process from wall time, or
use pipeline counts as elapsed shader-compilation time. No exact reducer-entry
timestamp currently exists in the cited receipt.

Reuse existing profiling. Add only the missing boundary needed to settle a
remaining attribution; no permanent telemetry framework or broad logging
campaign. Timed windows must not contain extra screenshots, readbacks or verbose
diagnostics added for inspection. Required thumbnail output readback stays
inside end-to-end thumbnail availability timing; moving it outside would hide
real cost. Additional inspection images are collected after the timed run.

Use the same82a package, producer, route, camera and ordinary process conditions
for comparable recovery measurements. Preserve cold and warm labels. If a
causal decision needs an A/B measurement, use a bounded interleaved control for
that family instead of comparing serial cohorts with unrelated source/package
changes. Saved baselines are sufficient for already-established defects; do not
rerun the entire broken inventory merely to populate another report.

Retain the existing goals: sub-50 ms feedback aspiration, sub-100 ms minimum
feedback, 100+ FPS steady behavior, no client freezes, and the existing explicit

The inverse query consumes only the current update's `entered` keys that the unchanged tile-replacement logic already decoded once. It never enumerates `target.senses.visible`, `seen`, another observer's mask, retained source geometry or the whole object store to find query cells. There is no second mask decode/list materialization for each support, object or index map. An entered cell remains authoritative even when it is in `tiles_unchanged`; tile-row presence is not the privacy predicate. Suppression output is clipped only to the exact entered membership, not the rectangle around it. If later code queries the raw mask directly, it must first reject points outside its x/y bounds and test the actual bit; bounds alone are not disclosed membership. Current tile semantics still require the one entered population: this plan does not claim to remove that necessary decode.

#### 4. Transaction and exact order

Each operation owns a new context shell. Reused inner index maps remain immutable until first write. A private `owned_maps` dictionary records which index outer maps were shallow-copied; per-map `owned_buckets` records which cell membership buckets were copied. These are ephemeral operation-local bookkeeping in the existing context, not persistent registries. At most one shallow copy of a map/bucket is needed per operation, even across several world updates. New cold indexes already own their maps. The prior accepted context is never mutated.

Publish the new context only in the existing successful reduction result and only adopt it at Journal's existing durable-rename success boundary (`_consume_admitted`, lines90–102). A later lineage, HUD, log-order or disk-rename refusal discards the private index along with the private canonical candidate. Replay rollback restores the previous context exactly, as it already does. Duplicate journal retries must return before doing index work.

Object candidates must not execute in cell-bucket discovery order. Current `prior_objects` and `disclosed.order` are populated during canonical retained-object iteration. Union candidate UUIDs, then sort them by the retained insertion ordinal from `object_order`. Explicit removals have already erased their entries. This reproduces the subset of current `target.objects.keys()` that can actually write anything. Untouched intervening objects produce no preimage/order output and may be skipped.

Ordinal maintenance mirrors **actual** store membership:

- overwrite / suppression / contents: retain old ordinal;
- erase: delete it;
- newly absent UUID assigned by `_object`: assign and increment `next_object_order`;
- remove then re-add the same UUID, even within one update: assign a new ordinal at its actual insertion, never reuse its old rank;
- several upserts: preserve the raw `object_rows` order, including current duplicate/overwrite semantics.

The existing tile `world_order`, entered iteration, first preimages, final row-identity comparison, `tiles_removed`, `objects_removed` and Compiler/Timeline replay remain unchanged. Sorting candidates by *current* ordinal cannot be used to order new wire rows or reconstruct erased-key reentry after the fact.

There is no early return around canonical validation and no partial index presented as complete. ##### B. Membership maintenance

```
replace_object_index(uuid, current_row, is_new):
    old = world.object_keys.get(uuid)
    supports = old.support_keys if old exists and old.placement == current_row.placement
               else keys(World.support_cells(current_row.placement))
    suppressions = old.suppression_keys
                   if old exists and old.suppressions == current_row.item.construction_suppressions
                   else unique Cells.key(point) for every suppression row.positions
    for key in old.support_keys minus supports: remove uuid from owned by_support[key]
    for key in supports minus old.support_keys: add uuid to owned by_support[key]
    for key in old.suppression_keys minus suppressions: remove uuid from owned by_suppression[key]
    for key in suppressions minus old.suppression_keys: add uuid to owned by_suppression[key]
    remove emptied buckets
    replace this object's immutable dependency record (own object_keys first)
    if is_new: assign next ordinal; increment scalar (own object_order first)

forget_object_index(uuid):
    use the existing per-UUID keys to remove all reverse memberships
    remove empty buckets and this UUID's dependency/ordinal entries

replace_connector_index(uuid, actual_connector_row):
    endpoints = unique Cells.key(point) for actual row.endpoints
    remove old-minus-new memberships; add new-minus-old memberships
    remove empty buckets; replace connector_keys[uuid]

forget_connector_index(uuid):
    remove memberships named by connector_keys[uuid]; remove empty buckets
    erase connector_keys[uuid]
```

`==` comparisons here are only for the touched object's concrete small dependencies; no world signature/serialization is computed. Placement is the resolved actual placement. A metadata-only dependency change may recompute this touched object's keys unnecessarily but must not skip a real support/suppression change. The cached dependency records are private immutable after-values; updates replace them.
