# Force construction source and ownership review

The installed Force membrane now uses the existing construction surface owner for formation, held pulse, actual hit impulses and Disintegrate collapse. This is bounded R12 work within the full implementation plan, not completion of R12 or N3.

Original inputs and ownership:

- `game_obsolete/construction_surface.py`, `construction_media.py` and `construction_media_lifetime.py` supply the original mesh/lattice, material, palette, impulse recurrence, joining and native member selection rules. Their files were read without modification.
- `world.construction_media[spell_construction.force.section].surface` owns the installed constants and donor references. Dome meshes are selected by the admitted radius; straight panels use the literal original lattice and the received tangent/height. No replacement world geometry or backend field was introduced.
- Invisible Force supplies disclosed physical objects and a construction owner, without a perceived spatial effect. Passive construction dates therefore remain with the existing physical construction family. Cold acquisition selects the original quiet phase; witnessed birth and native hit dates survive later operations and camera changes. The finite retirement track supplies its same existing lifetime to the preceding visible world until contact. Hidden Force is not drawn merely because its object remains remembered.
- Pending sections form individually. Held adjoining collinear sections of the same native owner, item, base and height use one original joined material and one original collapse mote group. Per-member hit nodes preserve the actual native object IDs, placements and native height; formation/destruction are noninteractive. Canonical objects, geometry and commits remain unchanged.
- Only actual admitted Hit/Crit attack events with an existing source body contact and received target position/height excite the original 144 Hz damped lattice. The original ten-second impulse window is retained. There is no inferred collision or damage.
- The original Force noise companion was absent from the installed media. Only `force/noise.rgba32f` was copied from the unchanged original construction operators (5,592,400 bytes, exact byte equality), with the existing file receipt. No JSON reimport or source-art edit was made.

Native records:

- `/recordings/force-construction/case.json`: 13 exact native SDK packets. Existing level-11 caster, existing spell grants and original Gloomplate; native See Invisibility at sequence2, a radius5 Force dome at `[7,5]` at7, and Disintegrate at12.
- `/recordings/force-panels/case.json`: 18 exact native SDK packets. Native path `[6,6] → [10,6]` creates two ten-foot members at7. An ordinary equipped Dagger attack hits the first member at12; native Disintegrate removes both at17. The source joins the held twenty-foot membrane while preserving both native identities.
- Both cases compare byte-for-byte with their own native server spools. No packet, outcome, HP, engine, SDK or definition was changed. Their saved server PIDs were stopped before a different workflow host reused port8827; that host was untouched.

Remembered-only Force produces no drawing.

- Dome and panel browsers sample 40 original-source views each. Repeat rendering has zero changed pixels and one final world pass. Context restoration is exact with zero new source decodes. Both actual post-destruction worlds have no Force drawings; disposal leaves zero views/leases (and zero panel hit entries), with owned targets destroyed. The actual world checks use an explicit directional review source; the Force material retains its original palette/emission behavior.

- The shared whole-Ice q0 formation/held/removal source and lifecycle regression passes after these changes. Independent bounded ECS/source readback found no ownership defect. Typecheck passed before the subsequent concurrent highlight additions.
