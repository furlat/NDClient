## Original findings that drove the repair

### P1 — Restore native environment colour; the present source reduction is destructive

`composition.ts:124` requests resolution .5 for environment colour. `resource-worker.ts:34–44` physically draws into a smaller Canvas with smoothing enabled. The source information is already lost before Pixi gets it. Nearest display sampling or ground-cache equality cannot restore it. Earlier nearest reduction visibly dropped grout segments; averaging reduces gaps by mixing colours and softening edges. This is the known source-policy mismatch, not evidence that Pixi nearest is broken.

Correction: remove the environment-specific reduction request and its now-unneeded worker reduction branch/parameter plumbing when there are no remaining consumers. Environment logical mounts and camera projection stay unchanged. Replace `environment-reduction.browser.mjs` expectations of physical 128×128/logical 256×256 with native-source fidelity. Its existing numeric-byte check remains useful. Do not process depth, normal, mask or radiance packets with cleanEdge.

### P1 — Ordinary rendering is still a dual pipeline, even when the visible result is a Sprite

`composition.ts:162–278` allocates the universal UniformGroup, Shader, Mesh, dummy bindings and several specialized parameters for every occurrence. `usesMaterial` at 732–739 sends ordinary images back through the Mesh for ambient/direct light, palette, body colour, components, condition animation, water and several other flags. `syncDisplay:766–785` lazily creates a second Sprite, then hides one route. Source/frame/tint data for the Sprite are still fetched from the Mesh shader's resources/uniforms.

Confirmed structural duplication: every ordinary Sprite pays for a hidden Mesh; any material custom shader breaks native Mesh batching. Timing of that cost alone has not been isolated. More seriously, these paths already produced different animation and tint output.

Correction: ordinary prepared images own a Pixi Texture/Sprite, source registration and only applicable filters. They must not allocate a Mesh or a universal shader merely to store frame data. Move authored colour/body/lighting operations onto that path, then delete `usesMaterial`, the hidden-route toggle, ordinary Mesh construction, and shader-as-source-storage. Specialized procedural geometry below is an explicit separate case, not an ordinary-image fallback.

### P1 — The old palette branches do not implement the requested exact swap

`surface-shaders.ts:191–196` accepts the nearest palette colour within squared distance .01 (RGB distance .1). The second route at 232–244 also uses .1 and a four-neighbour heuristic: an isolated matched colour is redirected to the primary target. These branches can change a source colour that is not in the requested map. Mode 3 also combines swapping with animated glints and emission. They must not be carried unchanged into an “exact swap” filter.

Correction: separate source RGB lookup from tint and material. Classify original byte RGB, preserve alpha, and leave every unmapped colour unchanged. If explicit swap and tint coexist, classify/swap before tint changes the lookup colour; ordinary clothes normally select tint alone. At translucent edges, unpremultiplying an RGBA8 premultiplied source cannot reliably reconstruct original RGB: low-alpha rounding is irreversible. Load an original straight PNG reference only for sources actually using exact swap; the existing numeric decoder can provide those raw bytes. Compare against that reference and output premultiplied colour. No global duplicate decode or new palette framework is needed. Test near-but-unmapped colours and partial-alpha edges, not merely palette centres.

`source-color.ts:8–10` intentionally reproduces old NeuroClient hue then broad white replacement; the old code is `/home/tommaso/Dev/NeuroClient/app/src/render/vfxFilters.ts:12–29`. That is an authored effect treatment, not the requested exact-swap implementation. Preserve its applicable authored behaviour under the material operation rather than presenting tolerance .5 as precision.

### P2 — Nonwhite tint still differs between the two existing routes

Sprite tint is assigned at `composition.ts:778`. The Mesh decodes source colour to linear (`surface-shaders.ts:270–272`), then multiplies by a separately linearized tint (`397`). Pixi Sprite multiplication uses the texture/tint encoded values. These are not the same operation.

Earlier independent browser probe: used the production setup from `sprite-sampling.browser.mjs`, changed tint to [128,96,64], disabled receiving and other colour operations, and compared ordinary Sprite against the neutral bodyColour-forced Mesh at zoom .73, 1, 1.37, 2.11. Body max difference was 4/255 with 176–1550 channels above tolerance 2; environment chest max 8/255 with 1089–9152 channels above 2; shadow max 1. No browser errors. The committed test uses white tint, so it cannot detect this mismatch.

Correction: the ordinary tint filter reproduces native Pixi tint multiplication before linear lighting conversion, with PMA preserved. Neutral filters must be an identity. Retiring the alternate ordinary shader then removes the divergence permanently.

### Already fixed — ordinary Sprite atlas animation invalidation

Current `composition.ts:769` sets `dynamic:true`; `772` calls `texture.update()`. This matches pinned Texture/Sprite semantics. Before the fix, `updateActorSamples` changed a real body's frame rectangle but produced zero changed output channels until `Sprite.onViewUpdate()` was forced; the forced refresh changed 28 channels. Root's new `sprite-animation.browser.mjs` passes ordinary frames 1/7/0, unchanged camera and zero new sources. No evidenced correctness problem with the fix. Preserve it in the Sprite-only implementation; do not re-open it as an outstanding bug.

## Source preparation and filter order

The smallest route matching the accepted assembled-character comparison is a retained native character composition, followed by a distinct cleanEdge GPU pass into a 2× physical target. It is not an offline requirement to preprocess every asset.

1. Select original frame and original numeric/raw references. Keep frame-local coordinates and atlas origin separate.
2. Apply only the chosen source operations to their actual source layer: precise swap where authored; ordinary tint for clothes; authored material for Magic2/spell layers. Do not tint an actor parent containing its magic, shadow and clothes together.
3. Preserve the existing combined/body/shadow/accent algebra and neutral endpoints in `character-material.mjs:21–99`. Body material treatment happens on its physical body branches before those parts are recombined. Do not cleanEdge the separate branch targets and then claim equivalence to cleanEdge of the visible assembled character.
4. Compose the selected character layers on their common native grid, retaining authored blend and sibling order. Ordinary modular actors currently have no such retained composition unless they have `bodyMaterials`; extend the existing source-composition owner instead of adding a second cache/service. Ground shadows and separately registered/world VFX remain separate. Attached character-sheet Magic2 remains isolated for its material before any approved final character assembly.
5. Run cleanEdge on the completed native colour result, with explicit frame boundaries, into `RenderTexture.create({width:W,height:H,resolution:2,scaleMode:'nearest'})`. Physical dimensions are 2W×2H; logical dimensions remain W×H, preserving pivots, sockets, scale and accepted proportions. Its neighbourhood samples must never cross into another atlas frame. The author implementation reads neighbours up to two source pixels away; do not confuse physical texels with logical dimensions or pixel ratio.
6. Draw the resulting Texture through the ordinary Sprite transform. Apply world lighting with the still-native geometry/normal companions mapped back to original frame coordinates. Keep viewport zoom separate from source processing.

Critical pinned Pixi caveat: `FilterSystem.mjs:475–528`, specifically line 492, selects the MINIMUM enabled resolution across an entire filter chain. Appending `cleanEdge.resolution=2` to tint/material filters set to 1 will still run that chain at 1. Use an explicit separate 2× pass from the finished native source; do not rely on that mixed-resolution chain. Source filters also must not first rasterize the actor at the current viewport zoom and then attempt to reconstruct its native pixels.

Cache only the current/requested appearance under the existing prepared-scene lifecycle. Dirty inputs are frame, facing/source, equipment/colour controls and material's actual sampled state; camera pan/zoom, lighting and world movement do not invalidate colour source preparation. Animated materials/glints can legitimately dirty it. Avoid an unbounded map of every frame×equipment×material time. Dispose private targets/filters on replacement and scene disposal; retain shared decoded sources under existing leases. Rebuild derived pixels after GPU generation changes. Allocate wither bounds and material ping-pong targets only when consumed, rather than for every ordinary character.

Alternative live cleanEdge sampling is technically possible, but a per-layer implementation makes edge decisions before layers meet and differs from the accepted assembled comparison; 21-neighbour sampling also repeats every displayed frame. A whole-screen filter would include floors, effects and already zoomed pixels and is incompatible with the selected source-only treatment.

## Lighting feasibility and guardrails

Pixi Filters can bind the current raw depth/normal/light TextureSources and map a screen-filter fragment back to a Sprite. This does not require another renderer plugin, a G-buffer, manual WebGL resource management or a new scene framework. Pinned `FilterSystem.mjs:267–289` implements `calculateSpriteMatrix` including Sprite world transform, anchor, logical original dimensions and cached render-group transform; `DisplacementFilter.mjs:48–57,70–86` demonstrates an extra TextureSource/sampler and this matrix during `apply`. FilterSystem `361–405` supplies logical input dimensions, physical input dimensions, valid pooled input clamp and output frame.

Carry the existing source-frame decode and transforms into a narrowly scoped lighting filter: geometry/normal region+sampling, source-to-local, camera-local basis, occurrence local-to-world, inverse-transpose normal transport, receiving controls, ambient field and direct emitters. Map from filtered Sprite coordinates to the ORIGINAL source frame before sampling companions; a 2× appearance target does not double geometry coordinates. Use the valid filter frame/clamp, not the pool texture's whole allocated dimensions. Account for frame origin/anchor and viewport clipping. Do not substitute `gl_FragCoord` for world/source position; offscreen filters change its origin. `water-shader.ts` currently uses framebuffer coordinates for its authored screen edge; preserve that intent explicitly if migrated.

Retain linear-light arithmetic and the existing distinction between ordinary premultiplied sRGB and Factory linear radiance. Paired Factory packets can have RGB at alpha zero (`registration.ts:74–75`, `appearance:261`, `surface-shaders:409–410`); a generic colour filter that discards alpha zero or treats those bytes as ordinary sRGB would lose emission. Preserve near/far painter order. No cleanEdge on those packets.

Current code correctly keeps geometry/normals as numeric no-premultiply nearest data and clamps ordinary appearance UVs to its frame. Current `dataAt:184–187` and `surface-shaders:367–395` implement ray-depth and normal decode. Preserve them before deleting the universal fragment. `paired-media.test.ts` validates CPU registration and normal perpendicularity but does not prove the replacement GPU filter. Actual lighting demonstrations in existing demos are a completion requirement: show an existing emitter lighting a receiving surface/body, rotate the camera, and preserve neutral/emissive appearance. Ground-cache's darkened ambient assertion is useful but is not that complete demonstration.

## Lifetimes, leftovers and measured versus unmeasured cost

Confirmed deletable GPU plumbing: `uPhysicalMask` and its map/rect/channel are declared but never sampled; `uSupports` is bound but not declared/consumed; rank/pass/first/previous/opaque/depth-bound/cutaway shader leftovers have no current ordinary fragment implementation. Stop loading/uploading unused mask/support GPU sources with those routes. Keep CPU support fields because ordering, patches and picking actually use them. Preserve delivered authored metadata; do not pretend an unused physical mask was functioning or invent its new semantics in this repair.

Confirmed avoidable allocations: all ordinary universal uniforms/Meshes; `body-composition.ts:58,70–72` always makes two ping-pong buffers and the wither bounds targets/mesh even when no wither pass exists; `composition.ts:194` creates an orbit admission texture for each orbit occurrence from identical field data. These are source-evidenced costs, not a measured explanation for a particular frame stall.

Risks worth guarding during the migration, not established current visual bugs: `composition.ts:199` and `body-composition.ts:63` mutate shared cached TextureSource sampler styles to linear/repeat for authored donors, while resource cache keys omit sampler policy. A filter can bind a separate TextureStyle for donor-specific sampling instead of changing another consumer's image. `bindImage:406–419` does not refresh `uPixelCenter`; no delivered frame sequence with changing convention was demonstrated. Actor sampling changes screen registration without updating its geometry matrices, but current ordinary actor sheets have no ray geometry, so this is not evidence of a present body-normal bug. Do not expand the repair into speculative geometry redesigns.

Current lifecycle positives: filter destruction exists in `releaseSprite:352`; source leases are released; private derived sources are destroyed; floor cache resets on geometry membership/lighting/quarter/GPU generation; resize ignores unchanged dimensions; warm pan/zoom checks have zero new source uploads. Ground cache is an appropriate Pixi static cache, not duplicate machinery to remove. Context restoration upload admission currently lists scene sprite sources but not `body.sources` (`111` versus `uploadSceneSources:319–322`); body generation redraw should lazily re-upload used donors, so visible corruption is unproven, but centralizing that existing source list avoids missing readiness guarantees for the new private source targets.
